# 密码本开放 API 对接方案（草案 v0.1）

> 目标：让开发者通过 API 读取用户已保存的账号密码，省去在自己的程序里手动输入密码。
> 状态：**方案待确认**，未开始编码。确认后按第四节分期实施。

---

## 一、场景与边界

**支持的能力**
- 第三方程序（浏览器插件、桌面脚本、自建服务）读取用户授权的密码条目
- 写入新条目（可选，按授权作用域开启）
- 查询密码库元数据（条目数量、容量）

**明确不做的事（红线）**
1. **不提供明文密码接口**。云端永远不解密，API 只返回**密文封套**，由调用方在本地用用户主密码解密。
2. 不提供"万能密钥"或服务端托管主密码的能力。
3. 不允许绕过用户在主小程序内的显式授权。

**为什么这样设计**：当前架构是端到端加密（主密码 → KDF → 本地加解密，云端只存密文）。若为 API 引入服务端解密，一旦云函数或数据库被攻破，用户全库明文暴露，与"密码管理器"的安全承诺直接冲突。因此 API 的安全模型必须与现有架构一致：**云端只做鉴权与密文搬运，解密发生在调用方本地**。

## 二、架构

```
用户（小程序）              云端（云函数/云托管）            第三方程序
   │                              │                            │
   │ 1. 生成设备授权码            │                            │
   ├─────────────────────────────►│  授权码入库（限时/一次性）  │
   │   （展示 6 位配对码）        │                            │
   │                              │◄──── 2. POST /v1/token ────┤
   │                              │       （授权码 + 设备标识） │
   │                              ├──── 3. 返回 vault token ──►│
   │                              │                            │
   │                              │◄──── 4. GET /v1/items ─────┤
   │                              │       （Bearer token）      │
   │                              ├──── 5. 返回密文封套 + meta ►│
   │                              │                            │
   │                              │                    6. 本地解密
   │                              │            （主密码 / 派生密钥）
```

**关键点**：第 6 步的解密在第三方程序本地完成，云端全程无明文。

## 三、接口设计（v1 草案）

### 3.1 鉴权流程

| 步骤 | 接口 | 说明 |
|---|---|---|
| 1 | 小程序内「API 授权」页面 | 用户点「生成授权码」→ 云端生成 6 位一次性码（5 分钟有效） |
| 2 | `POST /v1/token` | body: `{ code, device_name }` → 返回 `{ token, expires_in, scopes }` |
| 3 | 用户在小程序内确认 | 显示请求方设备名，用户点「允许」后云端签发 token（防钓鱼） |
| 4 | 撤销 | 小程序内「已授权设备」列表，一键吊销 |

**token 设计**
- 随机 32 字节，云端只存 `sha256(token)`，有效期 30 天，可续期
- 绑定 openid + 设备标识，支持多设备，任一吊销立刻失效
- 作用域：`items:read`（默认）/ `items:write`（需用户勾选）

### 3.2 数据接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/vault/meta` | 返回 `{ crypto_version, kdf, iterations, salt, verifier }`（公开参数，不含密钥） |
| GET | `/v1/items?since=&limit=` | 增量拉取，返回密文列表：`[{ id, type, title_cipher, fields: [{key, nonce, ciphertext, mac}], updated_at, is_deleted }]` |
| GET | `/v1/items/{id}` | 单条密文 |
| POST | `/v1/items` | 写入（需 `items:write`）：只接受**已加密**的封套，云端校验格式，不校验明文 |
| GET | `/v1/user/entitlement` | 容量/会员状态（非敏感） |

**响应中永不出现**：主密码、派生密钥、明文字段、解密的备注。

### 3.3 SDK（降低接入成本的关键）

提供 `@wuyou/vault-sdk`：
```js
const vault = new VaultClient({ token, masterPassword });
await vault.unlock();                 // 本地 KDF 派生密钥 + verifier 校验
const items = await vault.list();     // 拉密文 + 本地解密
const pwd = vault.getField(item, 'password');
```
- JS 版（Node / 浏览器插件）、Python 版（一期先 JS）
- SDK 内实现：KDF（PBKDF2-SHA256，参数取自 meta）、AES-GCM 解密、增量同步
- **SDK 不缓存密钥到磁盘**，进程退出即失效

## 四、分期实施

| 阶段 | 内容 | 预估 | 前置 |
|---|---|---|---|
| P1 | 云函数 `openapi`（token 签发/校验 + items 只读）+ 小程序「API 授权」页 + JS SDK + 限流审计 | 1.5 天 | 无（不依赖虚拟支付） |
| P2 | `items:write` 作用域 + 设备管理/吊销 UI + 审计日志查询 | 0.5 天 | P1 |
| P3 | Python SDK + 浏览器插件示例 + 开放文档站 | 1 天 | P2 |

**技术选型建议**：走 **HTTP 云函数**（`openapi`），不用小程序 callFunction——第三方程序无小程序身份，HTTP 更通用。云函数内自行校验 token，不依赖微信登录态。

### 安全加固（P1 必须包含）
- 令牌哈希存储、限时授权码、一次性使用
- 每 token 60 req/min 限流 + 异常告警
- 审计：记录 token、IP、UA、访问的条目 id（用户可在小程序查看）
- 返回体统一脱敏，错误信息不回显内部细节

## 五、风险与取舍

| 风险 | 影响 | 对策 |
|---|---|---|
| 用户把主密码交给第三方 SDK | 中高 | SDK 明确提示"主密码只在本地使用"；文档红线声明；不提供云端解密接口 |
| 第三方程序被盗导致 token 泄露 | 中 | 只返回密文，攻击者仍无法解密；可随时吊销 |
| 平台合规（API 对外提供服务） | 低 | API 不在小程序内运行，不影响小程序审核；但需在用户协议补充条款 |
| 运维成本（云函数 + 审计存储） | 低 | 限流 + 按需扩容 |
