## 二、上报什么（白名单）

只上报**元数据**：

| 类型 | 示例 |
|---|---|
| 阶段名 | `unlock_start` / `unlock_derived` / `unlock_nav_ok` |
| 耗时（毫秒） | `ms: 2380` |
| 布尔结果 | `ok: true` / `firstUse: false` |
| 错误码/错误名 | `name: TypeError`、`msg`（已截断 120 字符） |
| 设备环境 | `platform` / `system` / `model` / `brand` / 基础库版本 / 微信版本 |

## 三、绝不上报什么（安全红线 S-07 / K-04）

以下字段一律脱敏为 `[redacted]`，由 `miniprogram/utils/diagnostics.js` 统一拦截：

```
password / pwd / confirmPassword / newPassword / oldPassword
secret / token / apiKey / key / session
ciphertext / plaintext / content / mac / iv / salt / verifier
openid / signature
```

此外：
- **对象/数组一律丢弃**（避免整条记录被带上去）
- 单条字符串上限 120 字符
- 内存事件环上限 50 条（`getRecentEvents()` 可取，供后续「设置 → 诊断」页面显示）
- 上报失败**绝不影响业务**（全部 try/catch 包裹）

## 四、关键事件对照表（排查用）

| 事件 | 含义 | 看到它说明 |
|---|---|---|
| `app_init` | 冷启动环境上报 | 用户进来了，可看机型/系统分布 |
| `unlock_start` | 点了「解锁/设置密码」 | 提交链路启动 |
| `unlock_derived` | KDF 派生 + 校验完成（含 `ms`、`ok`） | **`ms` 就是真实解密耗时**；`ok=false` 表示密码不对 |
| `unlock_threw` | 解锁过程中抛异常 | 有异常，看 `name` / `msg` |
| `unlock_nav_ok` | `wx.reLaunch` 成功（含耗时 `ms`） | 正常进入首页 |
| `unlock_nav_fail` | 跳转看门狗判定失败 | **按钮卡死类问题的直接证据** |
| `unlock_nav_error` | `reLaunch` 回调 `fail` | 跳转被系统拒绝，看 `errMsg` |
| `app_error` | 全局 `wx.onError` | 未捕获运行时错误 |
| `unhandled_rejection` | 未处理的 Promise 拒绝 | 异步链路漏了 catch |

### 典型判读

| 现象（用户描述） | 日志应呈现 | 结论 |
|---|---|---|
| 「一直解密中」 | 有 `unlock_start`，无 `unlock_derived` | KDF 或校验卡住（真死锁） |
| 「一直解密中」 | `unlock_derived` 的 `ms` 很大（如 >20000） | 只是**设备太慢**，需要优化或提示 |
| 「解密完了进不去」 | 有 `unlock_derived ok=true`，无 `unlock_nav_ok` | **跳转失败**（正是 4.3.9 修的那类） |
| 偶发进不去 | `unlock_nav_error` 带 `errMsg` | 看系统拒绝原因，针对性规避 |
