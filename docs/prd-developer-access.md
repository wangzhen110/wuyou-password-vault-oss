# PRD：开发者密码中台（AI 可访问的密码 API）

> 版本：v0.1 草案 | 日期：2026-09-28 | 状态：立项讨论稿，未开发
> 前置依赖：无忧密码本 V1 正式上线（备案 + 提审通过）
>
> **历史讨论草案，不是已确认决策、当前功能承诺或实施计划。** 本 PRD 中的授权模式、MCP/API 架构、价格和会员权益均未据此核实或实施。唯一当前状态入口是[项目状态与路线图](项目状态与路线图.md)；相关技术提案也只是历史方案：[V2 技术提案](v2-technical-proposal.md)。

## 一、一句话定位

用户的密码库可以生成「开发者访问授权」，AI 编程工具（Cursor / Claude Code / WorkBuddy 等）通过 MCP 或 API 按权限读取密码，开发者从此不再手动翻密码本复制粘贴。

## 二、目标用户与场景

| 用户 | 场景 |
|------|------|
| 开发者 | 写代码时 AI 需要数据库密码、第三方 API Key、测试账号——AI 直接从密码库按权限取，不再打断心流 |
| 普通用户（进阶） | 在自己常用的 AI 助手里查「我 xxx 平台的账号是什么」，AI 代为取用 |
| 平台 | 第三方生态通过开放 API 接入（远期） |

## 三、候选设计（未确认）

### 3.1 授权模式：用户自选，两种并存

| 模式 | 行为 | 适用条目 |
|------|------|---------|
| **随时可取**（预授权） | 条目打上「API 可取」标签后，授权 token 范围内 AI 可直接读取明文，无需逐次确认 | 测试账号、开发密钥等低敏感条目 |
| **逐次确认**（审批制） | AI 每次请求读取明文，用户手机收到确认请求，当场点「允许」才放行（60 秒有效） | 生产数据库、支付密钥等高敏感条目 |

- 粒度：按条目设置，也可按标签批量设置
- 默认值：新条目默认「不可 API 访问」，用户显式开启
- 模式随时可改，改动立即生效

### 3.2 两阶段架构（未经批准/未实施的“零知识”目标提案）

> 本节的“零知识”是未来架构目标和评审假设，不是当前产品承诺、已批准决策或已实施/已验证能力；不得据此推断主密码库当前已达到零知识或云端全密文。

| 阶段 | 形态 | 架构 | 零知识是否破坏 |
|------|------|------|---------------|
| **V2（候选）** | MCP Server | 提案设想在开发者本机处理同步数据并由用户本机解密；密钥边界、缓存和威胁模型均需评审 | 目标是避免上传派生密钥；尚未实现或验证 |
| **V3（候选）** | 云端开放 API + 开发文档 | 提案设想隔离的自动化密码库与受作用域限制的 API token；数据隔离、密钥托管和访问控制尚无确认设计 | 主密码库与自动化库的安全边界不能仅靠 collection 隔离推断，需另行评审 |

> 业界先例：1Password Service Accounts、Bitwarden Secrets Manager 均采用「隔离库 + 作用域 token」模式。

### 3.3 安全铁律（任何阶段不可违反）

1. **主密码永不参与 API 链路**——服务器任何代码路径都不可能接触到主密码或其派生密钥
2. **明文返回受模式控制**——随时可取仅限显式打标的条目；逐次确认必须用户当场批准
3. **全量审计日志**——每次读取记录：时间、条目、调用人（token 标识）、返回方式；小程序内可查、可导出
4. **Token 最小权限**——作用域到条目/标签集合；可设过期时间；可一键吊销；吊销即时生效
5. **防提示词注入**——明文返回仅通过 MCP 工具结构化返回，并在文档中警示开发者不要把密钥拼进提示词

## 四、商业化假设（未确认）

| 权益草案 | 免费档设想 | 会员档设想（价格未确认） |
|------|------|---------------------|
| MCP Server 本地访问 | 1 个授权位，3 条条目 | 无限授权位、无限条目 |
| 审计日志 | 保留 7 天 | 保留 180 天 + 导出 |
| 云端开放 API（V3） | — | 会员专属 |
| 逐次确认模式 | ✅ | ✅ |

> 以上是待验证的商业假设，不是已上线权益或定价结论；目标用户需求、付费意愿与运营成本需要调研。

## 六、当时暂不考虑的方案（提案判断，未构成当前决策）

| 方案 | 否决原因 |
|------|---------|
| 服务器解密主密码库供 API 使用 | 破坏零知识承诺，等于放弃核心安全卖点 |
| 一次授权全库可读 | 违反最小权限；一次泄露 = 全库泄露 |
| 用微信消息做逐次确认通知 | 订阅消息一次性授权、到达率不稳定，不可靠；改用小程序内长轮询 |
| API 直接复用主密码库 collection | 无法做权限隔离，且云数据库权限模型撑不起 token 作用域 |
