# 云函数契约（action 级）

> **数据来源**：全部由代码静态提取（2026-10-22，脚本 `scripts/extract_design_specs.py`）。
> 每个 action / 事件 / 环境变量 / 错误码均可在对应 `cloudfunctions/<name>/index.js` 检索到；**无来源的内容不写入**。

## 1. login

**action**：无分支（单入口），核心是"登录 + 返回权益"

| 项 | 内容 |
|----|------|
| 入参 | 无（身份取自 OPENID） |
| 出参 | `success`、`capacity`、`user`、`invite_code` |
| 新建用户默认值 | `free_capacity: 10`（login:208）、`invite_capacity: 0`、`paid_capacity: 0` |
| 字段补齐 | `free_capacity === undefined` → 补 **20**（login:33）⚠️ 与 208 不一致 |
| 错误码 | `LOGIN_FAILED`、`USER_ID_UNAVAILABLE`、`USER_NOT_UNIQUE` |
| 活跃统计（2026-10-30 新增） | 写 `users.last_active_at = now`（与 `updated_at` 同一次 update）；当天首次登录时 `counters/dau_YYYY-MM-DD.value +1`（北京时间切日）。**计数为旁路指标：写失败只记日志，不影响登录结果** |

## 5. vpayCallback（虚拟支付推送）

**入口**：HTTP `/vpay`；支持 `echostr` 校验、安全模式 `Encrypt` 解密（`msg_signature` + AES）

**事件**：`xpay_goods_deliver_notify`（发货）、`xpay_coin_pay_notify`（代币）、`xpay_refund_notify`（退款）、`xpay_complaint_notify`（投诉）、`xpay_subscribe_ios_refund_query_notify`（iOS 退款问询）、`xpay_wxpay_callback_notify`（风控）

**应答**：`{ ErrCode: 0, ErrMsg: 'success' }`；iOS 退款问询需附 `IosRefundQueryResponse{result_code, result_info, evidence}`

**发货逻辑**：事务内 `deliver()` —— 校验订单 `pending` → 发权益（容量包 +10 / 会员 +365 天）→ 订单置 `paid` + `entitlement_delivered_at` → 清除 `pending_payment_order`

**常量**：`VIP_DAYS = 365`、`GRACE_DAYS = 3`、`INVITE_VIP_REFERRAL_DAYS = 90`、`INVITE_VIP_REFERRAL_WINDOW_DAYS = 30`、`PACK_CAPACITY = 10`、`PAID_CAPACITY_MAX = 30`
**环境变量**：`VPAY_APP_KEY`、`VPAY_APP_SECRET`、`WX_APP_ID`、`VPAY_ENV`、`VPAY_TOKEN`、`VPAY_AES_KEY`
**错误码**：`ORDER_NOT_FOUND_OR_AMBIGUOUS`、`ORDER_NOT_PAID`、`AMOUNT_MISMATCH`、`AMOUNT_MISMATCH_SERVER`、`MISSING_TRANSACTION_ID`、`ORDER_MISMATCH`、`DELIVER_FIELDS_MISSING`、`USER_NOT_FOUND_OR_AMBIGUOUS`

## 12. janitor（定时清理，2026-10-23 新增）

- **职责**：TTL 索引的替代方案（`tcb UpdateTable` 无 TTL 参数，实测）。每日 03:00 定时触发器（`janitor-daily`，7 段 cron `0 0 3 * * * *`）删除 `expire_at < now` 的记录。
- **清理范围（硬编码，不接受外部参数）**：`api_codes`（expire_at=创建+1 天）、`api_tokens`（=令牌到期）、`otp_requests`（=创建+7 天）、`api_audit`（=创建+90 天）。
- **调用**：仅定时触发器/控制台手动 invoke；无 HTTP 入口、无鉴权面（无外部参数）。
- **返回**：`{ success, cleaned: {集合: 删除数}, totalRemoved, errors[], ran_at }`。

## 11. 一次性读取交付（4.2.0 新增，`POST /v1/request` + `GET /v1/otp`）

AI 无需长期令牌即可发起；**云端全程只有"AI 一次性 key 加密后的密文"**。

| 接口 | 说明 |
|------|------|
| `POST /v1/request` | body：`{ client_name, purpose, entry_id, key_hex(64hex，AI 生成的一次性 AES key) }`；返回 `{ request_id, claim_secret, expires_in: 600 }`；限制：同 IP 每分钟 3 次、同用户待批 3 个 |
| 用户侧 | `apiAuth` 的 `list_otp_requests`（返回条目标题需端侧解密后展示）与 `decide_otp_request`（allow=true 时带端侧用 ai_key 加密的 delivery：`{iv, ciphertext, mac}`——4.2.14 起 encryptWithKey 附 EtM 的 HMAC（覆盖 iv+ciphertext），校验由 AI 侧完成，云端透传） |
| `GET /v1/otp?request_id=` | header `X-Claim-Secret`；**取件即焚**（返回后立即清空 delivery、status=consumed）；窗口 60 秒 |

**安全护栏**：单次仅 1 条条目（scope 绑定 entry_id）、待批准 10 分钟超时、批准后 60 秒取件窗、取走即焚不可重放、claim_secret 只存 sha256、全部进 `api_audit`（`otp_request_created/otp_approved/otp_denied/otp_consumed`）。

**泄露面（诚实标注）**：云端在批准后 60 秒窗口内同时持有 AI 的 key 与密文（被拖库且同时取走才可能解密）；明文只出现在用户设备内存（批准那一刻单条解密）。
