# 优化计划（2026-10-24）

> 背景：功能主体约 80% 完工，进入优化期。用户指定方向：**启动与首屏 → 空态与错误态 → 交互反馈统一**。
> 铁律：**每个阶段改完必须验证**（静态检查 + 单元测试 + 真机路径 + 视觉确认），未验证不得进入下一阶段。

---

## 阶段划分

| 阶段 | 内容 | 预期影响 |
|------|------|---------|
| **P1** | 启动与首屏体验 | 冷启动不再白屏，过渡自然 |
| **P2** | 空态与错误态统一 | 无数据/失败场景有明确引导，不再空白 |
| **P3** | 交互反馈统一 | 全站按压/加载/失败反馈一致 |

---

## P1 · 启动与首屏

### 现状问题
- 冷启动：锁屏页 → 首页为 `reLaunch` 硬切，无过渡
- 首页数据未回来时直接渲染空列表（看起来像"没有数据"而非"加载中"）
- 登录/同步状态无视觉提示，用户不知道在等什么

### 改动清单

| # | 文件 | 改动 |
|---|------|------|
| 1.1 | `pages/index/index.wxml` | 列表区加 **加载骨架**（3 条灰色占位行，纯 CSS，无图片）|
| 1.2 | `pages/index/index.js` | 增加 `listLoading` 状态：`loadData()` 开始时 true，完成/失败时 false |
| 1.3 | `pages/index/index.wxss` | 骨架样式 + 淡入淡出（`opacity` 过渡 200ms）|
| 1.4 | `pages/lock/lock.js` | 解锁成功后**延迟 120ms 再 reLaunch**，让锁屏淡出动画播完（不改变逻辑，只调时序）|
| 1.5 | `styles/theme.wxss` | 新增骨架色变量 `--skeleton-bg`（浅色 `#EEF1F0` / 深色 `#232B27`）|

### 验收标准
- 冷启动进首页：**先见骨架 → 数据到达后淡入真实列表**，全程无空白闪烁
- 数据为空时：骨架消失 → 显示空态（P2 的组件）
- 弱网（开发者工具"Slow 3G"）：骨架至少可见 1 秒，不闪

---

## P2 · 空态与错误态统一

### 现状问题
- 无记录、搜索无结果、网络失败、同步失败、加载失败——各页面文案/样式不统一
- 部分场景直接白屏或只有一行小字，用户不知道下一步做什么

### 改动清单

| # | 文件 | 改动 |
|---|------|------|
| 2.1 | `components/comp-empty/*`（新建）| 统一空态组件：`type`（empty/search/error/offline）+ `title` + `desc` + 可选操作按钮；**图形用纯 CSS 几何**（圆环 + 斜线等），不引入图片资源 |
| 2.2 | `pages/index/index.wxml` | 列表为空 → `comp-empty type="empty"`（"还没有记录，点右下角 + 添加"）|
| 2.3 | `pages/index/index.wxml` | 搜索无结果 → `comp-empty type="search"`（"没找到包含「xxx」的记录"）|
| 2.4 | `pages/index/index.js` | 加载失败 → `comp-empty type="error"` + 重试按钮 |
| 2.5 | `pages/settings/settings.wxml` | 备份取件/同步失败沿用现有弹窗，不重复做空态 |
| 2.6 | `styles/theme.wxss` | 空态配色变量（复用 text-secondary / divider）|

### 验收标准
- 四类场景各触发一次，**标题/说明/操作按钮齐全，无空白页**
- 搜索无结果时能显示用户输入的搜索词
- 错误态点重试能重新拉数据

## P3 · 交互反馈统一

### 现状问题
- `tappable`（按压态）已全局可用，但**加载态、禁用态、失败提示**各页面各写一套
- toast 文案长短不一，有的 1.5 秒有的 3 秒

### 改动清单

| # | 文件 | 改动 |
|---|------|------|
| 3.1 | `utils/feedback.js`（新建）| 统一封装：`toast(msg)`（1.8s）/ `success(msg)` / `fail(msg)` / `loading(title)` / `hideLoading()`，内部统一图标与时长 |
| 3.2 | 全站替换（分批）| 先替换 **settings / index / member / add / detail** 五页的 `wx.showToast` 调用；其余页面后续批次 |
| 3.3 | `components/comp-cell/*` | 补 `loading` 属性（右侧显示小 spinner，用于"手动同步"等耗时操作）|
| 3.4 | 全局 | 按钮禁用态统一：`opacity: 0.5` + `pointer-events: none`（已在部分页面，统一到 `tappable` 配套类）|

### 验收标准
- 全站 toast 时长/图标一致（成功 ✓、失败 ✕、纯文本无图标）
- 手动同步点击后：cell 右侧出现 spinner，完成后恢复状态词
- 禁用按钮点击无反应且视觉可辨

## 测试策略（每阶段必做，缺一不可）

### 1. 静态检查
```bash
node --check <改动的每个 js>
```

### 2. 单元测试
```bash
npm test        # 179 项必须全过
```

### 3. 关键路径回归（真机/模拟器，逐条走）
| # | 路径 | 关注点 |
|---|------|--------|
| R1 | 冷启动 → 锁屏 → 输入主密码 → 首页 | 骨架 → 数据淡入，无空白 |
| R2 | 首页新增记录 → 列表出现 | 新增后骨架不误触发 |
| R3 | 搜索关键词（有结果/无结果）| 无结果空态文案含关键词 |
| R4 | 断网 → 进首页 | 离线空态/错误态 + 重试 |
| R5 | 设置 → 手动同步 | spinner → 状态词变化 |
| R6 | 设置 → 备份密码本 | loading → 取件弹窗 |
| R7 | 会员页（演示模式）| 不显示购买入口 |
| R8 | 深浅色切换 | 骨架/空态/spinner 在两种主题下都可见 |

### 4. 视觉确认
- 骨架态、空态（4 类）、错误态、加载态 **各截一张图**，与设计预期比对
- 深浅色模式各走一遍

### 5. 交付前
- 包体积对比（不得显著增长，骨架/空态均为纯 CSS，预计 +2KB 内）
- 版本号升位并上传，提醒用户切体验版验证
