## 一、为什么重构（现状体检）

当前 UI 是 V1→V5 逐层打补丁长出来的，不是设计出来的：

| 问题 | 实例 |
|------|------|
| 样式重复 | index.wxss 405 行 / settings.wxss 419 行，卡片、按钮、空状态在每个页面各写一份 |
| 补丁痕迹 | 离线横幅、生物识别按钮、字体放大模式都是后来"塞"进去的，风格与原页面割裂 |
| 品牌残留 | 极简密码本 → 无忧密码本 改名后，各页标题/文案仍有旧叫法（需全局扫一遍） |
| 颜色不统一 | app.json 导航栏 `#07C160`，深色主题主色 `#2CD06A`，两套绿并存 |
| 间距随意 | theme.wxss 定义了 `--sp-*` 节奏，但页面里大量硬编码 rpx，没有真正执行 |
| 无组件复用 | 按钮、单元格、弹窗、空状态、密码输入框全是页面级重复实现 |

**结论：骨架（CSS 变量体系）是好的，肌肉（页面实现）是乱的。重构 = 保留骨架、重造肌肉。**

## 二、设计语言定调（V6）

延续现有 V5 反 AI 味规则（emoji 禁做图标、禁渐变紫、标题左对齐、8rpx 节奏、按压反馈），在此基础上定三条主轴：

### 2.1 主轴一：深色是本体，浅色是映射

- 深色为默认且唯一精心打磨的主题（`#121212` 底 + `#1E1E1E` 卡片 + 单一绿 `#2CD06A`）
- 浅色主题继续用 `theme-light` class 映射同一套变量，**不单独设计**——保证两主题永远同构，不出现"浅色页没适配"的回归
- 绿色只用于：主按钮、选中态、成功反馈。危险/警告各自独立色，不与绿混用

### 2.2 主轴二：三层表面系统

参照主流密码管理器（1Password / Bitwarden 深色模式）的层级做法，把"灰"分层并写死为变量：

| 层级 | 变量 | 深色值 | 用途 |
|------|------|--------|------|
| L0 画布 | `--bg-page` | `#121212` | 页面底 |
| L1 表面 | `--bg-card` | `#1E1E1E` | 卡片、导航栏、TabBar |
| L2 内嵌 | `--bg-input` | `#2A2A2A` | 输入框、标签、内嵌块 |
| 浮层 | `--bg-elevated`（新增） | `#262626` | 弹窗、下拉菜单、toast |

规则：任何界面元素必须明确属于某一层，禁止出现"第四种灰"。

### 2.3 主轴三：一套组件，七个页面

所有页面只用抽取后的组件拼装（见第三节），页面 WXSS 只允许写"该页面特有的布局"，不允许再出现通用按钮/卡片/空状态的实现。

## 三、组件库抽取清单

| 组件 | 替代现状 | 要点 |
|------|---------|------|
| `comp-btn` | 各页手写按钮 | 变体：primary / secondary / danger / ghost；统一 88rpx 最小高度 + btn-press 反馈 |
| `comp-cell` | settings 的全部行、detail 的字段行 | 左图标（纯CSS插槽）+ 标题 + 副文案 + 右侧（箭头/开关/值）；列表的原子单位 |
| `comp-card` | 首页密码卡片、设置分组卡 | 支持 card-press；内间距走变量 |
| `comp-empty` | 各页"还没有存密码" | 图标 + 一句话 + 行动按钮，三段式插槽 |
| `comp-dialog` | showModal / 手写弹窗 | 统一浮层层级 `--bg-elevated`；危险操作红色主按钮 |
| `comp-pwd-field` | 锁屏/新增页密码输入 | 胶囊样式、显示/隐藏切换、强度条（add 页用） |
| `comp-nav-bar` | 各页手写自定义导航 | 统一状态栏高度适配 + 返回 + 标题；锁屏页可隐藏 |
| `comp-tag` | 标签展示 | 用于条目标签 + 预留 V2 的「API 可取」标记样式 |

预估新增 ~8 个组件、总代码量比现在**减少约 30%**（重复实现收敛）。

## 四、信息架构（保持 2 Tab，不动导航结构）

```
TabBar
├─ 密码（index）
│   ├─ 搜索 / 列表 / FAB 新增
│   ├─ → detail（只读详情：字段复制、显示隐藏、编辑入口）
│   └─ → add（新增/编辑表单）
├─ 设置（settings）
│   ├─ 安全组：当时设想改主密码 / 生物识别 / 自动锁定 / 字体放大（生物识别当前不支持）
│   ├─ 会员组：member 页入口 + 权益展示
│   ├─ 通用组：主题 / 清理缓存 / 离线模式说明
│   └─ 关于组：agreement / 版本 / 联系反馈
└─ lock（独立解锁页，非 Tab）
```

- **不加第三个 Tab**。V2 的「开发者授权」页挂在设置 → 安全组下（会员入口旁），理由：目标人群小，不值得占导航位；上线后看数据再决定是否升级
- agreement 保持独立页（审核要求可见）

## 六、两个必须先定的决策

### 6.1 渲染引擎：本次继续 WebView，不上 Skyline

| 对比 | WebView（现状） | Skyline |
|------|----------------|---------|
| 伪元素/复杂选择器 | 完整支持 | 支持受限 |
| 纯 CSS 图标体系（依赖 ::before/::after） | ✅ | ⚠️ 部分写法失效，全部图标要重画 |
| 自定义 TabBar / 自定义导航 | 成熟 | 可用但坑多 |
| 迁移成本 | 0 | 全页面验证 |

纯 CSS 图标是本项目设计语言的根基，Skyline 会让它整体重写。**结论：V6 维持 WebView；Skyline 单独立项评估，不与本次重构捆绑。**

### 6.2 主题切换入口：本次不做

变量体系已支持 `theme-light`，但设置页加切换开关 = 多一条测试矩阵（每页×2 主题×2 字号）。V6 只保证"切到浅色不破"，不提供 UI 入口；入口放 V6.1。

## 七、重构纪律（防翻车）

1. **逻辑零改动**：只动 WXML/WXSS + JS 里绑定名对齐；不改任何加密/云调用/锁屏逻辑——重构期间发现逻辑 bug 只记录不顺手修
2. **一页一验**：每页重做完立即模拟器 + 真机各过一遍（深色 + 浅色 class + 字体放大模式三态），过完才动下一页
3. **提审版本兜底**：动工前给当前可用版本打 git tag（`v3.2.0-pre-refactor`），重构完成的版本若回归不过，随时可回退提审
4. **包体红线**：重构后主包 ≤ 300KB（现在 170KB，组件化后应持平或下降；任何图片资产一律进云存储，参考 avatar 教训）
5. **审核红线不动**：隐私指引入口、用户协议入口、无诱导分享元素——每页验收单固定三项
