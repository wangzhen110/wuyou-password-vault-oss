一、这是什么

开放 API 让第三方程序（脚本、插件、自建服务、AI 工具）读取你在无忧密码本里保存的账号密码，免去手动输入。

三条硬约束

  1. 接口只返回密文：ciphertext / iv / mac / salt，没有任何明文密码字段。
  2. 解密在调用方本地完成：需要用户的主密码，通过 KDF 复现密钥后自行解密。服务端不掌握主密码。
  3. 只读：本版本不支持第三方写入、修改、删除。

二、授权流程（三步）

① 用户在小程序：设置 → 开发者 → 开放 API 授权 → 生成授权码（8 位数字，5 分钟有效）
② 第三方：POST /v1/token { code, device_name }   → 202 pending_confirmation
   用户在小程序内看到设备名 → 点「允许接入」
③ 第三方：再次 POST /v1/token { code, device_name } → 200 { token }
  • 授权码一次性，用后即废，5 分钟过期。
  • 第三步必须重新提交；令牌只在这一次响应中出现，服务端只保存其哈希。
  • 用户拒绝 → 403 rejected_by_user；已用过 → 410 code_used。

不含 verifier：服务端不返回 verifier（它是离线猜测主密码的凭据）。校验主密码是否正确，靠「解密后 MAC 校验是否通过」。

3.3 拉取密文条目

GET /v1/items?since=<毫秒时间戳>&limit=100

{
  "success": true,
  "items": [
    {
      "id": "entry-1",
      "crypto_version": 1,
      "iv": "<32 位十六进制>",
      "ciphertext": "<偶数位十六进制>",
      "mac": "<64 位十六进制>",
      "salt": "<32 位十六进制>",
      "created_at": "2026-10-18T00:00:00.000Z",
      "updated_at": "2026-10-18T00:00:00.000Z"
    }
  ],
  "next_since": 1792290000000,
  "server_time": 1792290000000
}
  • since：只返回 updated_at 晚于该时间的条目（增量同步）。
  • limit：1–100，默认 100。
  • 排序：按 updated_at 升序，配合游标翻页不重不漏。
  • next_since：满页时返回本页最新时间戳，下次作为 since 继续；未满页为 null（已取完）。
  • 已软删除的条目不会返回。

增量同步标准写法

let since = 0;
for (;;) {
  const res = await fetch(`${BASE}/v1/items?since=${since}&limit=100`, {
    headers: { Authorization: `Bearer ${token}` },
  }).then(r => r.json());
  for (const item of res.items) await handle(item);
  if (res.next_since == null) break;
  since = res.next_since;
}

四、本地解密规范（必须严格一致）

格式：PBKDF2-HMAC-SHA256（60 万次）+ AES-256-CBC + Encrypt-then-MAC

4.1 派生密钥

material      = PBKDF2-HMAC-SHA256(masterPassword, salt, iterations=600000, dkLen=64)
encryptionKey = material[0..32)   // 32 字节，AES-256 密钥
macKey        = material[32..64)  // 32 字节，HMAC 密钥

4.2 验证并解密一条记录

认证数据（AAD）必须是这个顺序的 JSON 数组：

const aad = JSON.stringify([
  envelope.crypto_version,
  envelope.salt,
  envelope.id,
  envelope.created_at,
  envelope.updated_at,
  envelope.iv,
  envelope.ciphertext,
]);
  1. 计算 expectedMac = hex(HMAC-SHA256(key=macKey, msg=aad))；
  2. 与 envelope.mac 常量时间比较，不一致 → 拒绝该条（密文被篡改）；
  3. AES-256-CBC 解密 ciphertext（iv 为十六进制，PKCS#7 填充）；
  4. JSON.parse 得到条目对象（含 platform、account、password 等）。
created_at / updated_at 参与签名，不能省略或改写，否则验签失败。

4.3 完整 Node.js 示例

const crypto = require('crypto');

function deriveKeys(masterPassword, saltHex, iterations) {
  const material = crypto.pbkdf2Sync(
    masterPassword, Buffer.from(saltHex, 'hex'), iterations, 64, 'sha256'
  );
  return { encryptionKey: material.subarray(0, 32), macKey: material.subarray(32, 64) };
}

function decryptItem(item, encryptionKey, macKey) {
  const aad = JSON.stringify([
    item.crypto_version, item.salt, item.id,
    item.created_at, item.updated_at, item.iv, item.ciphertext,
  ]);
  const expected = crypto.createHmac('sha256', macKey).update(aad).digest('hex');
  if (!crypto.timingSafeEqual(Buffer.from(expected, 'hex'), Buffer.from(item.mac, 'hex'))) {
    throw new Error('MAC 校验失败：密文可能被篡改');
  }
  const decipher = crypto.createDecipheriv('aes-256-cbc', encryptionKey, Buffer.from(item.iv, 'hex'));
  const plain = Buffer.concat([decipher.update(Buffer.from(item.ciphertext, 'hex')), decipher.final()]);
  return JSON.parse(plain.toString('utf8'));
}

五、安全须知

  1. 主密码只在本地使用：任何要求你把主密码上传到服务器的服务都应视为危险。
  2. 令牌只授予「读取密文」的权限；即使泄露，攻击者仍缺主密码。
  3. 请勿把 encryptionKey / macKey 持久化到磁盘，进程退出即失效更安全。
  4. 用户在小程序内可随时吊销设备，吊销立即生效。
  5. 全部访问写入审计日志（时间、设备、条目数量、IP），用户可在小程序内查看授权设备。
