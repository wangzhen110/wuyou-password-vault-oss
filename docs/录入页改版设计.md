## 二、核心设计：候选来自「你自己的记录」

**不是**预置几百个平台，**而是**把已存记录的 `platform` 去重、按使用次数排序，作为补全候选。

| 场景 | 做法 |
|---|---|
| 进页面 | 「最近使用」横排 chips（前 6 个，按条数降序），点一下即填 |
| 输入平台名 | 实时过滤已有平台（前 8 条），显示条数，点选即填 |
| 无匹配 | 不拦截，直接用输入的名字保存 |
| 性能 | 只渲染前 6 / 前 8 条；全量数据放页面实例变量 `_allPlatforms`，不进 `setData` |

### 顺带修掉一个真实缺陷

旧 `onPlatformSelect` 只设 `selectedPlatform` + `accountHint`，**不写 `form.platform`**，
导致「选了微信」下面还要再输一次「平台名称」，可填成不一致 → 列表页分组会碎成多个组。
新版点选建议时**同时写入 `form.platform`**。

## 三、调研依据（两条独立来源，同一结论）

| 来源 | 原文 | 抓取 |
|---|---|---|
| **Ant Design**（企业级组件库）Select 文档 | 「当选项少时（**少于 5 项**），建议直接将选项平铺」「如果你在寻找一个**可输可选**的输入框，那你可能需要 AutoComplete」；`showSearch` / `filterOption` / `virtual`（虚拟滚动默认开启） | 2026-10-30 |
| **Flutter** 官方 API · DropdownMenu | 「People can also **filter the list based on the text input** or search one item in the menu list.」`enableFilter` / `enableSearch` | 2026-10-30 |

**结论**：选项少（<5）可平铺；选项多必须「输入即过滤」+ 只渲染可见部分。

## 四、布局规格（1rpx = 0.5px）

```
┌──────────────────────────────┐
│ comp-nav-bar                 │ 现有组件
├──────────────────────────────┤
│ 登录 | 服务器 | 银行卡        │ 类型 pills 28px（原 32）
├──────────────────────────────┤
│ 平台   [输入/补全]            │ 单行 46px（原 57 + 平台区 90）
│ 账号   [输入]                 │ 单行 46px
│ 密码   [组件自带]             │ 57px（保持 comp-pwd-field 不动）
├──────────────────────────────┤
│ 最近使用  [微信][企业微信]…   │ chips 行 ≈50px
├──────────────────────────────┤
│ 更多信息（选填）        ›     │ 折叠 40px（原 44）
├──────────────────────────────┤
│ [        保存        ]        │ 固定底部 44px（视觉），点击区 ≥48px
└──────────────────────────────┘
```

**省地方**：去掉横向平台选择区（≈90px）+ 平台/账号改单行（省 22px）= **省约 70px**

## 五、与现有实现的兼容（不破坏功能）

| 现有能力 | 处理 |
|---|---|
| 类型切换 + 模板动态表单（非 login） | **完全不动** |
| 自定义字段 | **完全不动** |
| 密码强度 / 生成 | **完全不动**（`comp-pwd-field` 不改） |
| 编辑模式回填 | 保留；编辑时也用补全 |
| 密保问题 / 密保答案 / 绑定手机 | **保留在「更多信息」折叠区**（不删 UI、不删数据） |
| 备注 | 提到折叠区第一位 |
| `onPlatformSelect` / `platforms` | 保留（不删代码），新增补全路径并行 |

> **为什么不删那 3 个字段**：它们是已存数据的载体，删掉 UI 会导致老记录里这些值**无法查看和编辑**，
> 属于数据可访问性损失（P-05 安全红线）。它们在折叠区里，**不占首屏**，已达到"少占地方"的目标。

## 六、不做的事

| 不做 | 原因 |
|---|---|
| 预置平台库（几百个内置平台） | B 场景不需要，维护成本高 |
| 平台分类表（社交/金融/购物…） | 同上 |
| 字母索引条 | 那是浏览几百个**内置**平台才需要 |
| 改 `comp-pwd-field` 组件 | 通用组件，改它有波及风险；密码保持原布局 |
| 删除密保/绑定手机字段 | 数据可访问性损失 |

## 七、验收标准

**功能**
1. 进页面显示「最近使用」chips（按条数降序，最多 6 个）
2. 平台输入「微」→ 出现补全（含已存平台，显示条数）
3. 点补全项 → 平台输入框**自动填入**（不再需要重复输入）
4. 无匹配时可直接保存
5. 编辑模式能正确回填
6. 非 login 类型（模板表单）行为**不变**
7. 自定义字段行为**不变**

**布局**
8. 平台、账号为**单行**（标签左、输入右）
9. 保存按钮固定底部
10. 首屏到密码字段底部 ≤ 300px

**工程**
11. `npm run test:gate` 全绿
12. 无 emoji 图标、无新增圆角值
