## 5. 订单状态机

```
下 单 ──> pending ──(发货成功)──> paid
              │
              └──(5 分钟未支付，下次下单时清理)──> closed (close_reason: pending_timeout)
```

| 状态 | 含义 | 依据 |
|------|------|------|
| `pending` | 已创建订单，等待支付/确认 | vpay/index.js:136 |
| `paid` | 已发货（权益已发放，`paid_at` + `entitlement_delivered_at` 写入） | vpayCallback/index.js:226-232 |
| `closed` | 超时关闭（`closed_at`、`close_reason`） | vpay/index.js:93 |

- **待确认订单 TTL = 5 分钟**：`PENDING_TTL_MS = 5 * 60 * 1000` `[依据: vpay/index.js:80]`
- 清理时机：**下次下单时**顺带把过期 pending 标为 closed（非定时任务）`[依据: vpay/index.js:88-95]`
- 同一用户存在未过期 pending 时，**拒绝新下单**并返回 `ORDER_PENDING` `[依据: vpay/index.js:82-86]`

> 注：代码中**没有 `expired` 状态**。曾误将测试单标记为 `expired`，已于 2026-10-22 修正为 `closed`。

## 5.5 条目编号（4.1.0 新增）

| 项 | 内容 | 依据 |
|----|------|------|
| 编号来源 | **服务端原子递增**：`counters` 集合文档 `_id: 'entry_seq'`，事务内 `value + 1` | sync/index.js `allocateEntrySeq()` |
| 分配时机 | `sync` 的 `upload` 落库前；已有编号则沿用（幂等），否则取新号 | sync/index.js `processUploads` |
| 编号范围 | **全局递增、删除不复用**（计数器只 +1，不回退） | 同上 |
| 存储位置 | 云端条目**外层字段** `seq`（明文，非加密内容） | sync/index.js `OPTIONAL_ENVELOPE_FIELDS` 含 `seq` |
| 本地缓存 | `entry_seq_map`（id → seq），**不入加密库、不入同步队列** | storage.js `applySeqMapping` / `getSeqMap` |
| 显示位置 | **仅密码列表行**（平台名前 `#N`） | index.wxml `.pwd-seq` |
| 未编号时 | 上传前本地无编号 → 列表不显示 | index.wxml `wx:if="{{item.seq}}"` |

> 已知限制：离线新建的条目要等首次同步成功后才显示编号（服务端分配）；编号不进入导出文件、不支持按编号搜索（当前范围）。
> 数据来源：代码静态核对（2026-10-22），非推测。

### 6.1 数据模型与一致性

id 规则、去重规则、seq 分配、加密与记录的对应关系、多设备同步的一致性模型与重构不变量，统一维护在 **[数据模型与一致性.md](./数据模型与一致性.md)**。

要点（2026-10-24 源码核对）：
- **记录 id = 端侧 16 字节随机 → 32 位 hex**，云端直接作为 `_id`
- **全程只按 id 去重，不做内容去重**（内容相同的两条是两条独立记录，刻意设计）
- **seq 由服务端按用户分配**，仅作展示编号，与 id 解耦

## 7.4 同步策略（2026-10-24 用户拍板）

| 触发 | 时机 | 间隔控制 | 实现 |
|------|------|---------|------|
| **登录强制同步** | 每次 login 成功（身份确认后） | 无限制，**必同步一次** | app.js `_login` 成功回调 → `sync.forceSync()` |
| **定时同步（前台）** | 小程序前台运行 | **每 1 小时** | app.js `_startSyncTimer` setInterval(3600s) → `sync.intervalSync()` |
| **回到前台** | onShow（含冷启动后） | 距上次自动同步 **满 1 小时**才跑 | app.js onShow → `sync.intervalSync()`（后台定时器会被挂起，此处兜底） |
| 手动同步 | 设置页「手动同步」 | 无限制 | sync.manualSync |
| 写入触发 | 保存/删除条目后 | debounce | 既有机制保留 |

- `intervalSync()`：内存级 `_lastAutoSyncAt` 时间戳判定，不足 1 小时返回 `{skipped:true}`（不产生请求）；`forceSync()` 重置时间戳后立即同步。
- 锁定时不自动同步（`globalData.isLocked` 直接跳过），避免锁定态无效请求。
