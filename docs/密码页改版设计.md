## 二、布局规格（1rpx = 0.5px，750rpx 基准）

```
┌────────────────────────────────┐
│ 状态栏                         │ statusBarHeight（现有 topBarHeight 逻辑）
├────────────────────────────────┤
│ [头像] 昵称 [会员]   已用12/500 │ 信息栏 92rpx（46px）
│                      ▬▬▬░░░░░  │   └ 容量条 6rpx 高，右侧 152rpx 宽
├────────────────────────────────┤
│ ☰   组名    条数          ＋   │ 工具栏 88rpx（44px）
├────────────────────────────────┤
│ [🔍 搜索平台、账号…        ✕ ] │ 搜索 88rpx（44px，常驻）
├────────────────────────────────┤
│ ▼ 微信                    5    │ 分组头 54rpx（27px）
│   [微] 微信工作号              │ 条目行 92rpx（46px）
│        wxid_work          ···  │
│ ...                            │
├────────────────────────────────┤
│ 密码 | 生成 | 我的             │ tabBar 92rpx（原生）
└────────────────────────────────┘
```

**顶部合计**：92 + 88 + 88 = 268rpx（134px）+ 状态栏 ≈ 160px
**对比改版前**：≈492rpx + 状态栏 ≈ 246px → **净省 86px**

### 抽屉（覆盖式）

| 项 | 值 | 依据 |
|---|---|---|
| 宽度 | **560rpx**（280px） | Material `design_navigation_max_width = 280dp` |
| 起始位置 | 信息栏下方（`top = 信息栏底部`） | 用户要求「信息栏不能被遮挡」 |
| 遮罩 | `rgba(0,0,0,.34)`，同样从信息栏下方开始 | 同上 |
| 圆角 | **仅右侧 16rpx**（与 --radius-md 一致，不新造） | 风格一致 |
| 动画 | `transform: translateX(-100%→0)`，`cubic-bezier(.22,.61,.36,1)`，240ms | 克制，不做弹跳 |
| 分组项高 | 88rpx（44px） | 微信热区 7–9mm |
| 关闭方式 | 点遮罩 / 选完分组自动关 | — |

## 三、交互规则

| 场景 | 规则 |
|---|---|
| 进页面默认 | 选中「全部」，平铺所有条目，**按录入时间倒序**（`created_at` 新→旧） |
| 选某平台分组 | 只显示该平台条目；组内按「工作/个人/其他」二次折叠（关键词匹配，见下） |
| 点分组标题 | 展开/收起该组；三角图标旋转 90°；高度用 `max-height` 过渡 220ms |
| 搜索 | 常驻框，输入即搜，**跨全部分组**过滤（名称/账号/平台），结果不再折叠；右侧 ✕ 清空 |
| 行右侧 `···` | 唤起底部操作面板：复制密码 / 复制账号 / 编辑 / 删除 |
| 抽屉底部 | 「新建分组」「编辑分组」 |
| 编辑分组 | 拖动 ≡ 排序、点名字直接改名、开关控制隐藏；「全部」固定不可动 |
| 隐藏分组 | 抽屉里不显示，数据仍在；编辑页可恢复 |
| 状态记忆 | 分组顺序、自定义名、隐藏项持久化到本地 storage |

### 组内二次折叠的关键词规则（v1 简化）

- 少于 3 条 → 不折叠，直接一个「全部 N 条」
- 否则按 `名称+账号` 匹配：`work|corp|企业|公司|shop|店` → 「工作/店铺」；`life|me|main|个人|生活|主号` → 「个人」；其余 → 「其他」
- **shortcut**：此规则是启发式，不保证准确 — 回填条件：用户反馈分类错乱时改为手动指定

## 四、风格约束（防「AI 味儿」— 用户硬要求）

### 必须复用现有令牌，禁止新造

| 用途 | 必须用 | 禁止 |
|---|---|---|
| 圆角 | `--radius-sm/md/lg` | 任意新圆角值、超大药丸形 |
| 阴影 | `--shadow-card` | 多层大阴影、发光 |
| 边框 | `1rpx solid var(--border-color)` | 无色块堆叠 |
| 主色 | `--color-primary` 体系 | 紫色/蓝紫渐变、彩虹渐变 |
| 字号 | `--fs-xs`~`--fs-xl` 档位 | 自造中间值 |
| 图标 | **CSS 绘制**（复用 `.search-icon-circle/.search-icon-line`）或现有 `.platform-icon` | **emoji 当图标**、图标字体、SVG 引入 |

### 明确禁止（AI 味儿清单）

1. ❌ 玻璃拟态 / 毛玻璃 `backdrop-filter`
2. ❌ 渐变文字、渐变按钮、发光边框
3. ❌ 卡片套卡片、每块都加阴影
4. ❌ emoji 作为 UI 图标（🔍 ＋ ☰ 等一律 CSS 画）
5. ❌ 弹跳/回弹动画、超过 300ms 的过渡
6. ❌ 平台图标改成圆形（现有是**圆角矩形** `.platform-icon` 80rpx + 首字母）
7. ❌ 引入第三方 UI 库 / 图标库

### 视觉校验方法

实现完成后，逐项核对：
- [ ] 新增样式里 `border-radius` 是否都来自 token
- [ ] 是否出现 `linear-gradient`（除现有品牌 logo 已有用法外）
- [ ] 是否出现 emoji 字符（`🔍 ＋ ✕ ☰` 都不许）
- [ ] 是否出现 `backdrop-filter` / `box-shadow` 叠多层
- [ ] 与「设置」「我的」页并排看，字号/圆角/间距是否同一套节奏

## 五、数据与持久化

| 数据 | 存哪 | 说明 |
|---|---|---|
| 分组顺序 | `storage` 本地键 `group_order` | 平台名数组 |
| 自定义组名 | `storage` 本地键 `group_names` | `{平台名: 新名}` |
| 隐藏分组 | `storage` 本地键 `group_hidden` | `{平台名: true}` |
| 手动新建空分组 | `storage` 本地键 `group_extra` | 平台名数组 |

**不同步云端**（v1）。理由：分组是**展示偏好**，不涉及加密数据；跨设备同步会引入冲突合并问题，当前不值得。
`shortcut: 分组配置仅本地 — 回填条件：用户提出换手机希望保留分组时`

## 六、不做的事（明确划界）

| 不做 | 原因 |
|---|---|
| 把某条记录移到别组 | 会破坏「同名自动归类」这条核心规则，需单独设计 |
| 分组配置云同步 | 引入冲突合并，当前过度设计 |
| 字母索引 / A-Z 侧栏 | 用户未要求，条目少时无收益 |
| 自定义分组颜色/图标 | 未要求，且易产生「AI 味儿」 |
| 改底部 tabBar | 保持原生，不动导航结构 |

## 七、验收标准

**功能**

1. 进页面看到「全部」平铺，最新录入的在最上
2. 点 ☰ 抽屉滑出，**头像与容量仍完整可见、未被遮罩覆盖**
3. 选「微信」→ 抽屉自动关、列表只剩微信条目、组内可折叠
4. 搜索框常驻，输入即时过滤，✕ 可清空
5. 行尾 `···` 可复制密码/账号、删除
6. 编辑分组可改名/排序/隐藏，重启小程序后仍生效
7. 只有 1 条的平台也显示为独立分组

**视觉**

8. 无 emoji 图标、无玻璃拟态、无渐变按钮、无新圆角值
9. 与现有页面并排无明显风格断层
10. 一屏可见条目 ≥ 11 条（改版前 6–7）

**工程**

11. `npm run test:gate` 全绿
12. 新增分组逻辑有单测覆盖
13. 版本号按 D-01 统一升级 8 处
